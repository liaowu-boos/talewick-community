# Versioned bounded retrieval

`retrieval.mjs` is a provider-free helper. `library-index-2` replaces the unversioned mixed raw/analysis search index. `buildRetrievalIndex(row,text)` indexes raw text alone, plus separate reviewed analysis entries only with approved source/text/analysis-bound review records. Index-only rebuild never reclassifies a candidate or changes review records.

On service startup or retrieval, an old/incompatible/unreadable ready index becomes `stale`. Retrieval excludes it and reports unavailable when no result can be supplied. Use the existing `retry(id,{stage:'index'})` explicitly. No automatic model call or repair is scheduled; historical packets remain untouched. Source summaries may expose `indexVersion`, including canonical version for duplicate registrations.

Query `evidenceType` may be `narrative` (default) or `performance`. There is no independent performance observation store yet: performance returns uncovered with an explicit explanation, even if a narrative index is stale. Unknown explicit source identities return unavailable. It never substitutes a narrative excerpt for performance data. The type is preserved in the query/packet.

Raw core windows are at most 700 JS characters except a single overlong line, which is never split. Ranking uses raw text exclusively, generic 2–4-character terms, weak-query-fragment removal and inverse window frequency; it does not understand negation, role attribution or psychological meaning. Reviewed analysis is separately ranked; its presence cannot change raw IDF scores. No model invocation is added. The optional existing candidate reviewer remains bounded and cancellation-aware.

Supply caps: 20 candidates, 6 units/materials and 12000 JS characters; caller restrictions are tighter. Raw units count as resulting continuous ranges; reviewed units count as unique IDs per material. Each source has at most 3 materials/4800 characters; a single continuous raw range is at most 2400 characters. Context expands at most 6 lines/280 characters per side and is included in every budget. Overlong complete fragments are skipped, never silently cut. Overlapping/adjacent same-source/version raw ranges are merged from actual source lines; disjoint ranges remain separate references. Reviewed related-unit evidence merges overlapping/adjacent intervals while preserving unit IDs and review provenance. Contained duplicate raw windows are omitted. When a same-source raw union exceeds 2400 characters, retain the independent complete windows if all source/global caps permit; report overlap explicitly in limits and charge repeated characters in each body. No partial clipping or gap bridging is allowed. Reviewed duplicate/overlap rules remain unchanged.

After the separate relevance assessor has marked a bounded set usable, final packing gives complete windows from different source versions an opportunity before filling the packet with additional material from the same source. It then maximizes the number of complete materials; when source and material coverage tie, it prefers lower unit occupation and finally the original candidate order. This allocator never adds an unreviewed/rejected candidate, clips evidence, increases a budget or re-scores relevance. If its actual packed coverage is not better than the prior ranked package, the prior package is retained. A changed package is identified in `limits`; packet fields and material/reference schemas are unchanged.

These are engineering limits, not validated semantic settings. Do not widen the budgets to fit all novel text. Multi-range coverage and matching words do not establish that a material is suitable, nor that a story will improve.
