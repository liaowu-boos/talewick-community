# 文件式资料库

当前采用本机文件存储。运行入口为 `createLibraryService({rootDir, ...})`，一个进程持有一个资料库目录。文件形式不会免除来源核对、分析复核或检索验证，也不代表必须把全部小说放进模型上下文。

| 文件或目录 | 保存内容 | 使用方式 |
|---|---|---|
| `objects/*.bin` | 上传原始字节及内容哈希 | 保存来源身份，不覆盖原件 |
| `objects/*.txt`、`*.lf-v2.txt` | 固定版本的可读原文 | 引文、行号和索引使用同一文本版本 |
| `catalog.json` | 来源登记、处理状态、当前分析、版本关系 | 由持锁服务原子更新，不手工切换分析或复核状态 |
| `analysis-versions/` | 历史分析快照 | 旧材料按旧版本回读，不能悄悄替换为最新分析 |
| `analysis-revisions/` | 候选提交、复核尝试、拒绝或发布记录 | 新候选先登记，获得有效独立复核后才发布 |
| `indexes/` | 原文窗口与已复核分析的派生索引 | 按问题有限召回，受候选、单元、字符及来源预算约束 |
| `relevance-reviews/` | 实际查询、候选、适用性判断和供给记录 | 用来区分没找到、被筛除、没供应、没有采用等原因 |
| `external-provenance/` | 单独保存的外部来历及补充资料 | 按明确来源与版本关联；不会自动获得当前分析的复核状态 |

分析保留事件、心理、情绪、表达、读者作用假说、定位证据和跨单元联系。可见行为、角色或叙述者的说法、分析推断要分别表述；读者作用仍是假说，不能写成已经验证的效果。

检索经过词法召回、有限上下文及可选的独立适用性判断，再按预算供给。创作另行决定采用或拒用。检索命中、分析经过 AI 复核、材料被采用、全文效果改善是不同结论，分别留证据。现行参数和局限见 [RETRIEVAL.md](RETRIEVAL.md)。

## 版本化资料修订

通过 `submitAnalysisRevision` 登记候选，不改变当前活动分析；显式请求独立复核并通过校验后，才通过现有事务归档、重建索引和发布新版本。旧引用继续绑定旧分析，可按原版本回读。外部编辑合同见 [submitted-analysis-contract.md](submitted-analysis-contract.md)。

`checked` 表示存在与本次分析绑定的复核记录，不等于全库内容正确或写作效果获得验证。独立 AI 意见须保留方法、版本和范围，不能写成人工审稿。

## 补充来源资料

`external-provenance/` 可保存明确关联到来源及版本的外部记录。仅附加文件不会使其进入自动检索或创作供给，也不会继承当前分析的复核状态。公开版不包含内部旧卡、小说库或派生观察；新安装仍为空资料库。

## 外部表现数据与后续迁移

Excel只是一种可能的输入来源，不是用户必须维护的中间步骤。表现数据应保存原工作表、行、时间口径和小说版本关联，缺失值不填成零；曝光、投流素材、金额、方式等混杂因素不归因到文本本身。文件库也能保留这些关系，通用Excel导入尚需独立实现。

后续是否迁移数据库，应根据实际并发写入、查询延迟、备份恢复、权限及跨记录查询需求判断。迁移不会自动修复错误拆解或证明检索素材适合创作。
