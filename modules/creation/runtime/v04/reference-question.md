# Optional primary reference question

2026-09-28 concrete-problem correction: a new `referenceStrategy` selection includes `storyProblem` with `relationship`, `trigger`, `desiredEffect` and `constraints`. The compiler puts this current problem into the primary query before the selected evidence relationship; choosing the same mechanism no longer discards the problem. The exact current-request quotation is still checked. The structured problem and mechanism fit remain model interpretations, not semantically verified facts. Unknown triggers must remain unknown; no standard emotional direction or resolution is imposed. The bounded compiled query must fit 240 characters, otherwise the existing requirements format repair applies; no truncation or extra query call is introduced.

The six-key strategy form is prompted for new tasks. The former five-key form remains accepted, but freshly compiling it now preserves its actual quoted need rather than returning the mechanism template alone. This legacy form cannot supply missing story dimensions; identical generic quotes may still produce identical questions. Already-saved requirements and queries are not recompiled or rewritten. Unsupported mechanisms and fact/performance needs retain the free-form question/intent route; no need and no material remain valid outcomes.

`context.targetUse.storyProblem` preserves the new problem separately from the original normalized requirements. It defines the target use, not a demand that a source repeat the target plot, names, profession or props. Source evidence must support the selected relationship and its necessary conditions on its own. A specific identity or means becomes necessary source evidence only when the user's actual question studies that identity or means. The context still fails explicitly above 8000 characters.

Connected V0.4 requirements extraction may return `referenceQuestion`: a string already trimmed, nonempty and no longer than 240 JavaScript characters. It is validated without normalization; invalid values use the existing one requirements repair. Omission (including JavaScript undefined) remains supported. There is no new model call or stage.

Select an actual reference need from the original request. Prefer the user's explicit writing problem; a profession or object alone does not request an encyclopedia or procedure. Explicit fact verification remains factual and requires direct evidence, never recast merely to match a narrative library. Expression questions ask for evidenced organization of action, cognition or narration, not identical target characters or events. No source answer, title or positive match is assumed.

With the field present, `LibraryQuery.query` is exactly its value. `context.referenceNeed` states the evidence purpose; `context.targetUse.requirements` preserves every normalized requirement except the two retrieval metadata fields (`referenceQuestion`, `retrievalHints`). Target conditions govern use in the new work, not source character/object identity. `retrievalHints` retains its existing schema and is forwarded as `recall`, never promoted into the primary question. The prompt asks for hints about the same question; semantic consistency is not enforced by the string validator.

The new context is serialized without truncation and rejected above the existing 8000-character service limit. Author requirements are not reduced. This size error occurs while constructing the query and stops the workflow; it is not classified as an empty library match or retried as a requirements format repair. Existing retrieval and material budgets are unchanged.

Without `referenceQuestion`, the legacy query/context construction is byte-compatible. This is a compatibility branch, not a claim that the old mixed-query semantics are fixed. Existing saved knowledge is restored without requery or replacing its query snapshot. No migration/backfill is performed.

The schema adds one optional field, so ordinary generated requirements may still drift from original specifications. Original request/context remain passed unchanged to extraction and repair; this feature does not impose deterministic semantic equivalence between fresh model requirements and earlier model requirements.
