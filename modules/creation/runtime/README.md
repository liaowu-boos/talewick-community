# 创作与整稿修订运行时

`workflow.mjs` 负责需求、规划、逐章写作、审稿与受限修订。保存点绑定本次请求、材料和正文版本；恢复继续使用已经保存的阶段。旧任务保留原模式，新任务的模式由产品服务写入请求规格。

## 资料采用与篇幅

`v04/planning-followup-decisions.mjs` 对规划后新增材料逐项记录采用或拒用。材料中的叙事观察只有随被采用的材料才能进入写作上下文；观察判断与原文引文分开校验。资料可用、实际供给和创作采用是三个不同状态。

`chapter-budget.mjs` 按已写正文计量剩余篇幅，为后续章节保留预算。没有足够空间时明确报告冲突，不返回伪装为正常范围的零字章节，也不截断已经保存的正文。机械篇幅符合要求不代表文学质量合格。

## 整稿修订

`whole-manuscript-revision.mjs` 导出 `runWholeManuscriptRevision` 与 `assertWholeRevisionResult`。产品通过现有任务接口提交 `kind: "revise"`、`revisionMode: "whole-manuscript-v1"`、完整 `chapters`、明确 `instruction` 和原稿 `baseRevision`；不能与选段模式混用。

流程依次冻结原稿、全文诊断、形成修改方案、修改受影响场景、独立复读，最后返回候选与差异。修改必须绑定方案及原文位置，保留范围外章节和受保护文本。没有充分依据时允许不修改。阶段保存点保留输入和响应绑定，恢复不重复已成功完成的调用。

结果的 `revisionApplied` 不表示已覆盖工作稿。产品单独展示候选，由用户整体采纳或保留原稿；任务期间若用户编辑了稿件，旧候选不能覆盖新稿。复读失败或提出风险时如实展示，不把候选生成当作质量通过。

## 连续性与验证

`continuity-chain.mjs` 对接跨章事件链检查。日期、持有人和交接关系需要正文依据；未能排除的解释与缺失证据保留为不确定状态。格式纠正有次数边界，失败记录不会通过重命名变成检查通过。

检查未完成时，结果可以明确标记 `qualityCheckStatus: "incomplete"` 并保存可读正文。独立 C01–C06 辅助检查和开发用事实小单元见 [验证模块](../../validation/runtime/README.md)。

从产品目录运行 `npm run test:runtime` 可复验公开的合成协议和恢复用例。它们验证程序约束，不验证模型的文学判断。
