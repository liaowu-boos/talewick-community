# 模块交接约定 v1

这些名称表示共享工作底稿中的内容，不要求用户填表，也不是已实现的 HTTP API、数据库或 JSON 校验器。简短任务可在已有记录中内联；长任务用文件路径和版本交接。未发生的检查写“未做”，没有材料写“未覆盖”，不为凑字段编造。

| 交接物 | 唯一维护责任 | 最少保留的信息 | 使用者 |
|---|---|---|---|
| RequestSpec | 需求与调度 | 任务类型；用户请求；输入文件及版本；题材/视角/时代/长度；必须保留与禁区；输出格式；方法选择；假设；确认点 | 本次被调用的模块 |
| KnowledgePacket | 知识调用 | 包标识/版本；来源入口；适用范围；所选方法；覆盖状态；选用观察及限制；未验证项 | 规划；确需材料的正文/修订 |
| StoryPlan | 故事规划 | 主角目标、压力和损失；主要承诺；行动链和章节接力；结局兑现；继承的事实与约束 | 正文与修订 |
| Manuscript | 正文与修订 | 稿件路径/版本；本轮内容范围；初稿或修订；连续性记录；已处理意见与未解决项 | 复核、交付 |
| ReviewReport | 质量复核 | 被读稿件版本；实际阅读范围及作者自检/独立 AI/真人来源；问题位置与依据；必须修/可选项；值得保留处；适用与未检查项 | 正文修订；调度 |
| DeliveryRecord | 文件交付 | 源稿版本；请求与实际格式；真实计量与命令结果；文件位置；PDF 程序核验与实际目视范围分别记；缺项 | 调度；产品端展示 |

同一物件的版本更新由其负责模块完成，其他模块通过交接提出修改。正文模块决定并记录如何修改，复核模块不直接覆写稿件，交付工具不改写故事。源稿格式与 CLI/manifest 契约继续以 工具说明 为准。

## 数据系统 → 知识调用

数据系统拥有原始小说、拆解记录、来源证据和知识包发布内容；知识调用模块拥有本次任务的选取记录。未来数据模块发布的包至少提供上述 KnowledgePacket 信息，并给出每条观察的来源与限制。现阶段使用包内静态材料可直接交接，不需要先接入完整数据库。

`coverage` 可记为 `covered`、`partial` 或 `uncovered`，只描述材料对当前请求的覆盖。另行保留 `evidence_status`（例如“本地抽象观察，未验证增益”），不把覆盖等同于有效性。`material_refs` 指向实际存在的材料，并带包标识和版本；证据只追溯到哪个层级就明确写到哪个层级。包内未带来源原文时，不伪称已检索或复核全文证据。

没有适用材料时交回 `coverage: uncovered`、空材料列表和原因，创作按通用流程继续；不自动启动数据拆解。新增外部知识包目前由执行者读取并按此约定整理，自动入库、选择与校验尚未实现。

## 独立复核的输入视图

ReviewReport 的独立阅读只接收必要稿件及中立规格，如字数目标、明确禁区、实际阅读要求。作者 StoryPlan、作者自评、预期结局答案、知识方法组别和其他审阅者结论不提供。修改后复核可以再提供原问题与改动范围，并说明是复读。全部底稿由调度保存，不等于所有模块或执行者都能读全部内容。

## 验证系统与产品端

单稿 ReviewReport 是生产意见；方法比较、读者反馈汇总和增益结论归项目验证系统。普通创作输出不能自动更新历史实验票或 `SYSTEM_GO`。

产品端以后读取任务阶段、确认点、稿件版本、ReviewReport 和 DeliveryRecord，提交用户选择与编辑版本。此约定定义交接内容；本轮没有新增模型服务、实时任务接口、账号服务或桌面安装程序。
