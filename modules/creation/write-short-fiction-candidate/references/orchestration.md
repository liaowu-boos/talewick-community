# 需求与调度

负责解释用户要做什么、安排调用和保留任务状态。具体写法由规划与正文模块维护，文学判断由复核模块维护，文件处理由交付模块维护。

输入：用户自然语言、用户指定文件及已有任务记录。输出：[RequestSpec](contracts.md)、本次执行路线和当前产物位置。

## 整理需求

区分新作、续写、修稿、仅诊断、仅格式转换。采用用户已明确的题材、主角目标、时代、视角、篇幅与禁区；普通偏好未指定时作合理假设并简短告知，关键设定冲突或不可替用户决定的事项集中问一次。需求模板 供执行者整理，不是用户必填问卷。

新作未另定规格时沿用候选默认：中文当代短篇、稳定单一视角、约 9000–11000 汉字、完整结局；该万字规格参考 8–12 章。用户另定篇幅时，章数随内容安排，不硬套万字规格。续写和修稿继承原稿及用户要求，不用新作默认改掉已有设定。交付格式按用户要求；没有另定时提供 TXT/PDF/ZIP，缺 PDF 能力时按交付模块说明如实交付可用格式。

用户只要小说时仍在内部完成必要规划与检查，正文不夹分析。只有加载技能、讨论方法或模块维护任务时，不自动开始创作新故事。

## 路由

| 用户任务 | 执行路径 | 保留的交付范围 |
|---|---|---|
| 新作 | 知识调用 → 规划 → 正文 → 复核 → 集中修订 → 必要复核 → 交付 | 完整小说及必要说明 |
| 续写 | 读完指定前文 → 整理已有事实 → 必要知识/剩余规划 → 续写 → 复核修订 → 交付 | 继承前文的续稿；用户要全文时交完整稿 |
| 修稿 | 读原稿与真实反馈 → 定位问题 → 必要局部规划 → 正文修订 → 复核 → 交付 | 原授权范围内的修订稿 |
| 仅诊断 | 读指定文本 → 复核 | 问题、证据与建议；不改正文 |
| 仅转换 | 交付模块接收原稿 → 必要格式整理并另存 → 检查/导出/核验 | 格式转换文件；不改写剧情 |

只需要导出时不重做创作；修改错字不重新选知识方法。用户指定分阶段确认时，将确认点记录在需求中并遵循。

## 任务状态与交接

使用同一份 工作底稿 记录当前阶段、已完成产物的路径/版本、下一动作以及确有的阻塞。模块只更新自己负责的段落，交接依据见 [接口约定](contracts.md)。恢复任务时读取最后的需求与产物，避免重新生成已经完成的部分。

为独立复核者另给中立阅读任务与指定稿件；共享底稿中的作者方案、自评、组别及其他评阅结论不随之提供。已有读者意见保留原意，用户已确认其真人来源时不反复索取证明。

默认新作一次初稿和一次汇总修订。用户另有授权时依其范围；同范围已确认的格式和工程错误连续修复。修订后核对原问题与相邻内容，再交付；尚未解决的故事问题如实列出，不自行换前提或追加试验批次。

每次修订与导出使用新路径，原稿及历史反馈保留。普通作品的继续交付不以新增真人问卷、方法增益结论或旧八稿控制器投票为前提；不修改这些历史结论。
