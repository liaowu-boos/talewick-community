# 只读审稿

**输入：** Manuscript（明确版本的实际稿件）及本次适用的中立 RequestSpec；修后复核可加此前 ReviewReport 中的问题及改动位置。

**输出：** ReviewReport（阅读者类型、实际阅读范围、原文位置与依据、必须修与可选建议、值得保留的场面、未解决项及结论边界）。交接内容可用自然语言或 Markdown 维护，定义见 [交接约定](contracts.md)，不是已实现的 API。

**负责范围：** 实际阅读并报告问题，保持输入稿件只读。所有正文修订交给 [正文模块](manuscript.md)；报告不充当修改后的稿件，也不替创作系统作实验验收。

## 既有六类问题范围

沿用项目已有范围，不新增审计类别，不要求穷举所有可能风险。针对实际文本指出位置和依据，不为填模板制造问题。

| 既有范围 | 要判断的阅读问题 |
|---|---|
| STORY_COMPREHENSION_BLOCKER | 核心事件、目标、动机、时间线和关键对象价值是否能复述 |
| LOCAL_CAUSALITY_BLOCKER | 相邻话语、行动和转场是否必须靠读者猜补才能成立 |
| GENRE_PROMISE_BLOCKER | 故事自身确立的类型期待是否实际兑现，而非强套另一题材 |
| FALSE_ENDING_BLOCKER | 第四章是否已把主问题写完，后续只能另起炉灶 |
| CH4_CONVERSION_CUT_BLOCKER | 若采用第四章切口，读者有没有具体待看结果，第五章有没有接住 |
| FULL_ARC_CAPACITY_BLOCKER | 目标篇幅内是否有非重复行动、代价、中段改变与完整收束 |

默认规格有第四章时保留对应承接要求；用户要求更短或没有第四章的作品，记录该项不适用，不伪造位置，也不拿它卡住交付。自定规格稿不混入原八稿实验。

## 实际阅读与记录

有独立执行者时优先由非作者阅读完整稿，先只给本稿与必要的中立任务；不提供 StoryPlan 中的预期答案、自评分、方法组别或其他核对者的结论。没有独立阅读就明确记录作者自检，不虚构席位。

若任务需要记录真实第四章第一反应，实际只读到第四章并保存当时记录，再继续读完整稿。已经知道结局就标为复读，不能倒签初读信号。普通审稿不因这一规则自动创建四章试读或新增读者席位。

读完后简要复述主角目标、触发、行动和结局，再记录必须修的问题与可选编辑建议，并保留值得保留的场面。每项注明章节、短引文或可定位段落，说明阅读影响；区分明确矛盾、语义歧义、个人口味和需核实的专业细节。不要把“字数达标”“对账对上”“能猜到”当成好读。

修后复核围绕原问题及改动，检查是否损伤相邻因果、时间、知情、物件和情绪。实际只读了局部就记录局部阅读，不登记为完整阅读。报告可放在 工作底稿 或独立文件中，并指明所读稿件版本，避免把旧稿意见冒充新版结论。

## 结论边界

- 工具说明 中的 `check` / `verify` 只检查格式及文件一致性，不判断以上文学问题，也不输出文学合格票。
- AI 自检、非作者 AI 阅读与真人反馈分开记录；不能因缺真人而代答，也不能因没有新问卷就永久暂停普通作品交付。
- 已收到的意见按原意保留。用户已经确认真人来源的，不反复要求口令或补声明。
- “未发现本轮改动引入的明确矛盾”不等于“所有读者喜欢”，更不等于“方法 B 胜过 A”。未解决项如实保留，不另换前提凑成功。
- 不计算新权重、总分、票数或 SYSTEM_GO。真实对照验证须独立明确任务范围，不用本包补造历史回执；普通创作及现稿兼容演练不是正式独立前向复现。

现实与原创问题仍落在既有范围：核对已知的知识来源、常识和能力边界，不复制来源独特表达、人物组合与连续情节；工具做不到的不能保证。没有文字重合不证明法律合规或商业成功。ReviewReport 说明实际读了什么、发现什么和未验证什么，不认证真人质量认可、方法增益或商业效果。
