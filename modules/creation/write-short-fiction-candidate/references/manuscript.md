# 正文与修订

**输入：** RequestSpec、适用的 StoryPlan、KnowledgePacket；续写或修稿还需原稿及已有反馈，汇总修订可接收 ReviewReport。

**输出：** Manuscript（实际稿件、稿件版本及路径、完结状态、必要连续性记录、已改与未解决项）。交接内容可用自然语言或 Markdown 维护，定义见 [交接约定](contracts.md)，不是已实现的 API。

**负责范围：** 写正文、续写和落实已确认的修订。审稿由 [审稿模块](review.md) 产出只读意见，文件检查与导出交给 交付模块。本模块不能把“已经修改”记成“已经独立复核”。

## 继承需求并连续完成

以用户要求和 RequestSpec 为准。新作按 StoryPlan 写完；续写先读完用户指定前文并继承事实；修稿先读原稿和反馈，保留核心意图，只处理授权范围。用户只要诊断时不改正文；仅格式转换由交付模块处理，不偷偷润色。

按 RequestSpec 连续完成本次稿件与修订；新作的默认轮次由 [调度模块](orchestration.md) 维护，用户已授权的修订范围优先。不要在大纲、第四章或导出前逐步停下索取授权，用户明确要求分阶段确认时依其要求。只对缺少的实质选择或超出授权的行动询问。

用户只要小说时，内部规划与检查仍执行，正文中不夹分析、组别、机器评分、工作笔记或他人反馈。每次修订另存新路径，保留原稿和首稿，不覆盖历史试读包、反馈及正式主 Skill。

## 把行动和后果写在读者能看见的地方

- 若有导读，提出值得追下去的局面，第一章承接并发生新行动，避免完整重演背景。
- 上一章的选择应在下一章产生后果。若采用第四章跳转切口，先让读者知道具体等什么；第五章先回答既有动作的后果，再扩展同一主线。不另开四章试读任务；短篇幅或没有第四章的作品不强造该位置。
- 转换时间、地点或在场人物时，补足理解所必需的衔接。邀请、联系电话、钥匙、清单、知情来源等仅在影响行动时交代，不把一切过程写成流水账。
- 在 工作底稿 中保留会改变后文的连续性事实，并随写作更新。账本帮助发现遗漏，不能替代正文中的场景与交代。
- 中段安排新阻力、策略改变或代价，不用调查资料、反复争吵和等待别人后悔填字数。
- 保留主角自己的错误和损失，让对手能够更新信息；不把主角的不负责写成胜利。
- 结局以实际完成的行动收束外部目标和关系变化；想法、承诺、合同或“准备去做”不自动等于事情已经完成。

依 KnowledgePacket 的适用范围使用抽象观察，不为覆盖条目塞人物和情节，不复制来源的独特表达、人物组合与连续情节；保留知识来源、常识和人物能力边界。

## 依据实际问题集中修订

逐章写作时同时参考本章情节任务、篇幅范围、完整已写前文和剩余预算。已写篇幅偏长时，控制后续展开尺度、减少重复交代；偏短时不把差额自动摊给后章。本章任务已经完成、衔接自然，就在合适位置收束。例如预计 900–1100 汉字而实际 850 汉字，不能单凭这项差额追加内容。必要行动和结局也不能因剩余预算不足而被截断。

最终计量只核对实际篇幅。字数不足或超出本身不启动自动扩写、压缩或回修；新增内容必须解决具体的必要行动、场景或因果交接缺失。重复心理描写、对白复述和无关景物不得作为补字手段。全书未达用户范围时如实报告偏差，不能悄悄改目标或宣布达标。

读完整稿、ReviewReport 和真实反馈后，集中定位需要修改的点。将“看着突然”落实为缺少哪个前置动作，“不知道谁说话”落实为哪一段指代不清，“没结尾”落实为结果缺失或收束重心分散；不能凭笼统负评全篇重写。区分明确矛盾、语义歧义、个人口味和待核实的专业细节，反馈按原意保留。

HFC7R5 的既有修订只提供局部经验：顾客到场前补邀请、试取餐开始前补约定、多人物同场时明确必要指代、行动已证明的道理少解释一遍、结账结果与情绪尾声尽量集中。这些不是新增审计类别，不要求每篇都有顾客、取餐或结账桥段。

语句精修不机械删除第一人称、对白、情绪停顿或亲情段落。若本次任务使用 humanizer-zh 等风格技能，只处理需要解决的重复解释和僵硬语言，不能用风格评分覆盖故事判断。

改后核对修改处与上下文，再读收束段；需要审稿模块复核时传递新版稿件及原问题位置。记录本次改动、实际检查范围和未解决项。默认完成本轮集中修订即交付；同范围、已确认的工程与格式错误连续修复，不重新索取每一步授权。不得另换前提凑成功、追加批次或等待用户尚未要求的读者补表，也不把未解决的故事问题宣布成项目永久 NO_GO。

## 交接实际稿件

Manuscript 应指向真实文件，说明是完整稿、未完稿还是诊断对象，以及本次修订对应哪个版本。完整小说按 工具说明 的源稿格式整理；保留段内原文、空格和标点，不为通过完整稿检查器给未完稿伪加“（完）”。实际格式检查由交付模块执行。

提交完整稿时，先请求实际阅读，再按已授权范围处理汇总意见。无独立执行者时注明作者自检；AI 阅读不代替真人反馈，机械计量通过不等于小说好看。未解决项随交接保留，让交付说明能够如实报告。
